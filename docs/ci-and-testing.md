# CI и тестирование

## Что проверяет первый этап

Workflow `CI` запускается для каждого pull request, push в `master` и вручную
через `workflow_dispatch`. Устаревший запуск для той же ветки/PR отменяется.
Четыре независимые проверки:

| Проверка | Окружение | Действия |
| --- | --- | --- |
| Check SDK matches its copy in Example | Ubuntu 24.04, Python 3 | Совпадение 1:1 путей и содержимого всех `.swift` в `CTChat/` и `Example/Chat/CTChat/` |
| Build SDK | macos-15-intel, Xcode 16.4 | Сборка пакета `CraftTalk` для iOS Simulator |
| Test SDK | macos-15-intel, Xcode 16.4 | XCTest на iPhone 16 / iOS 18.6 |
| Build Example app | macos-15-intel, Xcode 16.4 | Debug-сборка схемы `Chat` для устройства без подписи |

Сборка SDK и тесты отображаются отдельными статусами в PR. Тестовая job сама
собирает пакет и тестовый bundle через `xcodebuild test`; артефакты сборки
между jobs не передаются.

Xcode и runtime выбраны явно; отсутствие окружения завершает проверку ошибкой,
а не переключает её незаметно на другую версию. Состав образа может меняться:
при обновлении сверяйте [описание образа GitHub](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md)
и проверяйте весь workflow. Локальная проверка на другом Xcode не заменяет запуск Actions.

Права workflow — `contents: read`; секреты и Apple Developer signing не нужны.
Публикация релизов, TestFlight и настройка branch protection не выполняются.
Лимит проверки копий — 5 минут, каждой Xcode job — 30 минут.

## Локальные команды

Нужны macOS, полный Xcode, принятая лицензия/установленные компоненты Xcode,
Python 3 и iOS Simulator runtime. Command Line Tools отдельно недостаточно.
Из корня репозитория:

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
python3 scripts/sync-sdk.py --check
bash scripts/ci.sh build-spm
bash scripts/ci.sh test-spm
bash scripts/ci.sh build-example
```

Это те же скрипты, которые использует CI. Они выбирают Debug, схему `CraftTalk`
для пакета и `Chat` в `Example/Chat.xcworkspace` для приложения.
SDK использует UIKit, поэтому тестирование через macOS `swift test` не подходит.

Чтобы явно использовать другой установленный симулятор:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun simctl list devices available
SIMULATOR_OS=27.2 SIMULATOR_DEVICE='iPhone 18 Pro' bash scripts/ci.sh test-spm
```

Скрипт по умолчанию ищет iPhone 16 с iOS 18.6. `EXPECTED_XCODE_VERSION=16.4`
в CI дополнительно проверяет версию Xcode; локально эта проверка включается
только при явном задании переменной. `DEVELOPER_DIR` не меняет глобальный `xcode-select`.

Example собирается с `CODE_SIGNING_ALLOWED=NO` и
`IPHONEOS_DEPLOYMENT_TARGET=15.0`, переданными **только в командной строке**.
Override нужен для сборки старых targets приложения/Pods современным Xcode;
он не меняет настройки в Git и заявленный минимум SDK. Полученная сборка
не доказывает поддержку iOS ниже 15. Удалить override можно после отдельного
согласованного обновления deployment settings и зависимостей с проверкой сборки.
Используются закоммиченные Pods, `Podfile.lock` и `Pods/Manifest.lock`;
`pod install`/`pod update` для CI не нужны. Общая схема `Chat` хранится в Git.

## Два стартовых теста

`CraftTalkTests` — XCTest target Swift package с `@testable import CraftTalk`.
Он проверяет настоящую `CTSecurityPolicy`, не меняя публичный API:

1. HTTPS разрешён для исходного и явно разрешённого хостов.
2. HTTP и HTTPS на постороннем хосте отклоняются.

URL используют домены `example.com`; запросы в сеть не выполняются.
Тестам не нужны сервер, сертификаты, Firebase или состояние `CTChat.shared`.
После тестов скрипт читает сводку `.xcresult`: требуется не меньше двух
успешных тестов, без ошибок и пропусков. Нулевой набор не считается успехом.
При расширении набора этот порог можно поднять; он не ограничивает число тестов.

Проверки реальных TLS-соединений, редиректов Foundation/WebKit, одноразовых
вложений, cookies, POST и очистки файлов **пока не реализованы**.
Локальный HTTPS-сервер, WebKit-регрессии и вторая версия iOS — следующий этап.
Успешный CI также не подтверждает исторически заявленную поддержку iOS 9.

## Синхронизация SDK

Источник истины — `CTChat/`. Копия — `Example/Chat/CTChat/`.

```bash
python3 scripts/sync-sdk.py --check
python3 scripts/sync-sdk.py --sync
```

`--check` ничего не меняет: сравнивает относительные пути и байты всех `.swift`,
сообщает об отсутствующих, отличающихся и лишних файлах и возвращает ненулевой
код при расхождении. В CI используется только этот режим.

`--sync` добавляет отсутствующие и обновляет отличающиеся файлы из корня.
Перед первой записью проверяет все изменяемые назначения: staged/unstaged
изменения, удаления и существующие untracked-файлы нельзя перезаписать.
Назначения с флагами Git `assume-unchanged` или `skip-worktree` также нельзя
перезаписать: команда прекращает работу до первой записи и не снимает флаги.
Если в копии есть лишние Swift-файлы, команда прекращает работу; их нужно
разобрать и удалить явно вместе со ссылками Xcode. Символические ссылки
в каталогах SDK не поддерживаются. Совпадающие файлы не переписываются.

Для новых Swift-файлов отдельно добавьте ссылки в проект Example и
Compile Sources target `Chat`: скрипт не редактирует `.pbxproj`.
Не используйте reset/checkout для обхода защиты локальных изменений.

## Диагностика и проверка ошибок

Каждая команда создаёт отдельный каталог в `artifacts/ci/` с полным
`output.log`, `.xcresult`, а для тестов — списком симуляторов и JSON-сводкой.
`ARTIFACTS_DIR` позволяет выбрать другой каталог. Повторные запуски не стирают
старые результаты. DerivedData находится в `.build/ci/` и не загружается как артефакт.
Не запускайте локальные SPM build/test одновременно: они используют общий DerivedData.

GitHub Actions загружает диагностику через `if: always()` и хранит 14 дней,
в том числе при ошибке сборки или теста. При ошибке до создания `.xcresult`
останется текстовый лог; при принудительной остановке runner загрузка не гарантируется.
`pipefail` сохраняет ошибку команды при выводе через `tee`. Предупреждения
старого кода остаются видимыми и сами по себе не превращены в ошибки.

Для проверки инфраструктуры в отдельной временной копии репозитория:

- Изменить зеркальный Swift-файл: `--check` должен завершиться с кодом 1;
  `--sync` не должен затереть незакоммиченное изменение.
- Временно инвертировать assertion: `test-spm` должен вернуть ненулевой код,
  сохранив лог и `.xcresult` с упавшим тестом. Затем удалить временную копию.
- Проверить успешную сводку: выполнено два теста, оба прошли, пропусков нет.

Первый реальный запуск Actions после публикации изменений необходим для проверки
закреплённого runner и скачивания артефактов. Локальные результаты подтверждают
работу скриптов только в локальном окружении.
