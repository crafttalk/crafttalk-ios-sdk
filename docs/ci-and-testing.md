# CI и тестирование

Порядок расширения покрытия и статус этапов: [план тестирования](testing-plan.md).
Правила написания и ревью тестов: [качество тестов](testing.md).

## Что проверяет CI

Workflow `CI` запускается для каждого pull request, push в `master` и вручную
через `workflow_dispatch`. Устаревший запуск для той же ветки/PR отменяется.
Пять независимых проверок:

| Проверка | Окружение | Действия |
| --- | --- | --- |
| Check SDK matches its copy in Example | Ubuntu 24.04, Python 3 | Совпадение 1:1 путей и содержимого всех `.swift` в `CTChat/` и `Example/Chat/CTChat/` |
| Build SDK | macos-15-intel, Xcode 16.4 | Сборка пакета `CraftTalk` для iOS Simulator |
| Test SDK | macos-15-intel, Xcode 16.4 | XCTest на iPhone 16 / iOS 18.6 |
| Test WebKit user flows | macos-15-intel, Xcode 16.4 | XCUITest тестового приложения на iPhone 16 / iOS 18.6 |
| Build Example app | macos-15-intel, Xcode 16.4 | Debug-сборка схемы `Chat` для устройства без подписи |

Сборка SDK и тесты отображаются отдельными статусами в PR. Тестовая job сама
собирает пакет и тестовый bundle через `xcodebuild test`; артефакты сборки
между jobs не передаются.

Xcode и runtime выбраны явно; отсутствие окружения завершает проверку ошибкой,
а не переключает её незаметно на другую версию. Состав образа может меняться:
при обновлении сверяйте [описание образа GitHub](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md)
и проверяйте весь workflow. Локальная проверка на другом Xcode не заменяет запуск Actions.

Права workflow — `contents: read`; секреты и Apple Developer signing не нужны.
Публикация релизов, TestFlight и настройка branch protection не выполняются.
Лимит проверки копий — 5 минут, каждой Xcode job — 30 минут.

## Локальные команды

Нужны macOS, полный Xcode, принятая лицензия/установленные компоненты Xcode,
Python 3 с модулем ssl, OpenSSL CLI в PATH и iOS Simulator runtime.
Стенд использует стандартную библиотеку Python, дополнительных pip-пакетов нет.
Command Line Tools отдельно недостаточно.
Из корня репозитория:

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
python3 scripts/sync-sdk.py --check
bash scripts/ci.sh build-spm
bash scripts/ci.sh test-spm
bash scripts/ci.sh test-ui
bash scripts/ci.sh build-example
```

Это те же скрипты, которые использует CI. Они выбирают Debug, схему `CraftTalk`
для пакета и `Chat` в `Example/Chat.xcworkspace` для приложения.
SDK использует UIKit, поэтому тестирование через macOS `swift test` не подходит.

Чтобы явно использовать другой установленный симулятор:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun simctl list devices available
SIMULATOR_OS=27.2 SIMULATOR_DEVICE='iPhone 18 Pro' bash scripts/ci.sh test-spm
```

Для выбранных сценариев совместимости (точный состав также проверяется):

```bash
UI_TEST_MANIFEST=Tests/ui-compatibility-tests.json SIMULATOR_OS=18.6 SIMULATOR_DEVICE='iPad (A16)' bash scripts/ci.sh test-ui
UI_TEST_MANIFEST=Tests/ui-compatibility-tests.json SIMULATOR_OS=17.4 SIMULATOR_DEVICE='iPhone 15' bash scripts/ci.sh test-ui
```

Без `UI_TEST_MANIFEST` выполняется весь UI-набор. Указанный JSON должен содержать
непустой список уникальных имён из основного манифеста; выбранный состав сохраняется
в `selected-tests.json`. Поднабор не считается полным прогоном. Команда `test-ui`
включает code coverage в `.xcresult`.

Скрипт по умолчанию ищет iPhone 16 с iOS 18.6. `EXPECTED_XCODE_VERSION=16.4`
в CI дополнительно проверяет версию Xcode; локально эта проверка включается
только при явном задании переменной. `DEVELOPER_DIR` не меняет глобальный `xcode-select`.

`test-spm` и `test-ui` берут тип устройства/runtime найденного симулятора и создаёт **новый**
одноразовый симулятор. Он устанавливает синтетический системный CA только туда,
запускает HTTPS-стенд на loopback и выполняет XCTest. После успеха, ошибки тестов
или обрабатываемого SIGINT/SIGTERM сервер останавливается, симулятор удаляется.
Существующий симулятор и хранилище сертификатов macOS не меняются.
Прямой запуск `xcodebuild test` без стенда завершит интеграционные тесты ошибкой;
для полного набора используйте `test-spm`.

Example собирается с `CODE_SIGNING_ALLOWED=NO` и
`IPHONEOS_DEPLOYMENT_TARGET=15.0`, переданными **только в командной строке**.
Override нужен для сборки старых targets приложения/Pods современным Xcode;
он не меняет настройки в Git и заявленный минимум SDK. Полученная сборка
не доказывает поддержку iOS ниже 15. Удалить override можно после отдельного
согласованного обновления deployment settings и зависимостей с проверкой сборки.
Используются закоммиченные Pods, `Podfile.lock` и `Pods/Manifest.lock`;
`pod install`/`pod update` для CI не нужны. Общая схема `Chat` хранится в Git.

URL используют тестовые домены; внешний сервер и Firebase не нужны.
`CTAuthenticationChallengeTests` создаёт challenge без serverTrust и проверяет
только выбор действия, ошибки и completion; это не подтверждение TLS-handshake.
Конфигурационные тесты передают Info.plist через внутренний источник значений
отдельного `CTChat`, без присваивания salt/URL в обход `configure`.
Компонентные сетевые тесты этапа 1 используют изолированный `URLSessionConfiguration` с `URLProtocol`,
который записывает запросы и отвечает локально; по завершении ожидают инвалидирования
сессии. Планировщик push управляется тестом без ожидания реальных пяти секунд.
Отдельный компонентный тест удерживает два настоящих task в URLProtocol и
синхронно вызывает data-callback SDK для download → push до завершения загрузки.
Он проверяет разделение буферов при заданном порядке; доставку callbacks системой
проверяет HTTPS-набор, чей тест push/download не заявляет гарантированного порядка ответов.
Два публичных DER в [Fixtures](../Tests/CraftTalkTests/Fixtures/README.md) созданы
специально для тестов разбора конфигурации; приватных ключей в репозитории нет.
Это не проверка TLS или доверия сертификату.

Интеграционные тесты этапа 2 используют настоящий URLSession без URLProtocol.
[HTTPS-стенд](../scripts/https-fixture.py) создаёт CA, intermediate и leaf на каждый
прогон. Валидные leaf имеют актуальный короткий срок; expired/future — намеренно
невалидные сроки. Для изолированного SecTrust дата берётся из конфигурации прогона,
сетевой поиск intermediate отключён; реальный TLS проверяет текущее время.
Отсутствующий intermediate подписывает отдельный leaf, поэтому кеш предыдущей
успешной цепочки не скрывает его отсутствие.

Порты выбирает ОС, слушающие сокеты привязаны к `127.0.0.1`; два хоста — `localhost`
и `127.0.0.1`, без изменения DNS/hosts. У каждого теста UUID, маршруты, журнал,
URLSession и каталог файлов. Сервер умеет возвращать статусы, редиректы,
Set-Cookie, задерживать ответ до явного разрешения теста, разрывать соединение
и обрывать тело. Журнал фиксирует фактические метод, тело и заголовки только
синтетических запросов. Взаимодействия синхронизируются событиями с timeout,
а не произвольными sleep.
Барьеры `hold` (15 секунд) и `holdAfterHeaders` (30 секунд) заканчивают ответ
успешно только после `release`. По таймауту соединение закрывается без ответа
либо с неполным телом, а ошибка записывается в `fixture-errors.json`. Она сохраняется
после сброса сценария и делает результат общего скрипта ненулевым даже при успешном
XCTest. Существующий ненулевой код `xcodebuild` сохраняется. `reset` и остановка
стенда отменяют ожидания без отправки оставшегося тела.
Перед `test-spm` и `test-ui` выполняются четыре Python-теста барьеров на loopback:
явный release, таймаут обоих режимов, reset и остановка. Отдельная команда:
`python3 -m unittest discover -s scripts/tests -v`. Это проверка стенда, не TLS SDK.

Системное доверие проверяется отдельным синтетическим CA в системном хранилище
одноразового симулятора: этот CA не передаётся через `trustedRootsByHost`.
Проверяются системный CA без дополнительных корней и вместе с другим CA SDK;
частный CA SDK без явной конфигурации остаётся недоверенным. Это проверка
совместной работы механизмов доверия, а не аудит всех встроенных публичных CA.
Методы описаны Apple: [добавление CA в Simulator](https://developer.apple.com/videos/play/wwdc2020/10647/),
[сохранение системных anchors](https://developer.apple.com/documentation/security/configuring-a-trust).

Приватные ключи находятся только во временном каталоге процесса и удаляются.
В `Fixtures/Runtime/` временно записываются публичные DER и конфигурация портов;
каталог исключён из Git и удаляется после прогона. Стенд откажется перезаписывать
существующий Runtime — это защищает другой запуск. После SIGKILL/аварии машины
автоматическая очистка не гарантирована: проверьте PID запуска, затем удалите
только его Runtime/временный каталог и симулятор с UUID из `fixture.json`.
Не выполняйте общий reset keychain или удаление остальных симуляторов.

Тесты владеют отдельными временными каталогами. Тесты моста используют локальный
HTML, непостоянное хранилище WebKit и свой экземпляр `CTChat`; удаляют обработчики
сообщений и останавливают загрузку после завершения. Изменений `CTChat.shared` нет.

После тестов скрипт читает сводку и дерево `.xcresult`: требуются **ровно 121**
успешных тестов из [явного списка](../Tests/expected-tests.json), без ошибок,
пропусков и повторов. [Проверка результатов](../scripts/verify-test-results.py)
сравнивает идентификаторы, поэтому одинаковое число не скрывает замену сценария.
При добавлении/удалении/переименовании тестов обновляйте манифест и эту таблицу
вместе. CI не генерирует ожидаемый список из текущих исходников.

## WebKit UI-тесты

`bash scripts/ci.sh test-ui` собирает [тестовое приложение](../Tests/WebKitHost/)
со схемой `CraftTalkUIHost` и выполняет `CTWebKitUITests`. Приложение компилирует
канонические исходники `CTChat/`; оно отдельно от Example, Pods и production-виджета.
Xcode-проект и общая схема хранятся в Git, XcodeGen для CI не нужен.
`project.yml` описывает проект для его обслуживания; при регенерации нужны
временные Runtime-ресурсы, которые обычный запуск создаёт автоматически.
Минимум iOS 15 у test host не меняет deployment settings SDK.

Настройка выполняется публичными `configure(security:)` и `configure()` через
настоящий `Bundle.main`: runner создаёт Info.plist с адресом локального HTTPS-стенда.
Legacy использует синтетический leaf `CTCertificate.der` в bundle; новый режим —
CA по хостам. Проверки доверия WebKit остаются включены, ATS-исключений нет.
UI-тесты выполняют настоящие нажатия XCUITest, а HTML создаёт отдельно программные
click, редиректы, iframe, Shadow DOM, формы и blob. Сервер записывает реальные
GET/POST, тела и cookies; журнал учитывает HEAD-probe, одноразовые маршруты
отвергают повторный запрос.

Приложение наблюдает страницу через чтение JS, файлы и слабые ссылки на
контроллер/WebView. Оно не заменяет delegates SDK и не вызывает их вручную.
Снимки состояния доступны по отдельному HTTPS-каналу, в том числе при открытом
системном меню. Для `tel/mailto` test-only UIApplication
фиксирует передачу URL системе; звонок и почтовое приложение не запускаются.

Набор содержит **42 UI-теста** из [отдельного манифеста](../Tests/expected-ui-tests.json).
Проверяются публичная настройка/JS/push, навигация и доверенные нажатия, загрузки,
точные байты файлов, отсутствие probe/replay, сохранение страницы/черновика/cookies,
ошибки, повтор, освобождение экрана и очистка незавершённой загрузки при освобождении.
Общая проверка сохранения чата ждёт доступности поля, пробует ввод через XCUITest
и возвращает исходный черновик. JS-снимок должен быть получен чтением, начатым
после контрольного наблюдения; ошибка очищает кеш и публикуется отдельно.
Отдельный сценарий намеренно ломает JS-чтение, проверяет отсутствие старого снимка
и восстановление наблюдения без перезагрузки страницы.
Оба публичных configure дополнительно проверяются с автоматически вычисленным hash
посетителя: salt из Bundle.main, публичный CTVisitor и независимый эталон в JS.
Вложения в iframe и клики внутри iframe проверяются напрямую и через HTTP 302:
по одному GET на переход, cookies, одноразовый файл, неизменные страница и черновик.
Повторные открытия в обоих режимах проверяют освобождение controller/WebView
через слабые ссылки; отдельно проверяется закрытие после blob и во время WKDownload.
Legacy-preview дополнительно проверяет настоящие нажатия «назад» и «поделиться»:
повторное меню сохраняет файл для preview, «назад» удаляет файл/каталог и позволяет
открыть другое вложение без перезагрузки чата и потери черновика. Для этих двух
сценариев host задаёт только accessibility-метки существующим кнопкам, не меняя
их targets/actions или геометрию. Публичным API задаётся пустой push-токен:
native legacy push использует системное доверие и не принимает частный pin
WebView-стенда. Проверка отсутствия ошибок остаётся включённой.
Secure и legacy также проходят два ухода в фон через Home и возврата через
activate: сохраняется введённый пользователем черновик, страница не перезагружается,
после возврата работают WKDownload с cookies либо blob-мост. Отдельно проверяется
возврат с открытым legacy-preview, сохранение его файла и кнопки отправки/закрытия.
Host наблюдает реальные applicationDidEnterBackground/applicationDidBecomeActive.
Это обычный фон/возврат без завершения процесса ОС; длительная приостановка,
восстановление после выгрузки приложения и фоновые загрузки не заявляются покрытыми.
Конкуренция проверяется удержанием тела первой загрузки на сервере: второй
WKDownload либо blob получает одну ошибку download/code=6, не создаёт новый
каталог и не показывает меню. Первая загрузка сохраняет точные байты; после
её завершения и закрытия меню повтор второй попытки проходит с очисткой файлов.
Для второго WKDownload первый GET уже доходит до сервера до отказа; повтор
проверяется отдельным нажатием на обычный URL без кеша. Первая загрузка одноразовая.
Отмена интерактивного «назад» проверяется настоящим edge-жестом и наблюдением
`transitionCoordinator.isInteractive` / `isCancelled`: отдельно с активной загрузкой
и с legacy-preview. Второй тест обнаружил удаление файла до решения об отмене
перехода; он сохранён с исходным assertion, без skip/expected failure. SDK не исправлен,
поэтому текущий полный набор нельзя считать зелёным.
Последний полный локальный UI-прогон после правок тестов 13.11.2026, Xcode 27.2,
iPhone 16 / iOS 18.6: **41 passed / 1 failed** из 42, без пропусков и expected failure
(`artifacts/ci/test-ui.fwf8kc/`; точные идентификаторы сверены с манифестом).
Единственное падение — прежняя отмена legacy-preview; SDK и её assertions не менялись.
SPM после исправления серверных барьеров: **121 passed**, без ошибок и пропусков
(`artifacts/ci/test-spm.mwWQre/`, пустой `fixture-errors.json`). После этой правки также
прошли **6/6 выбранных UI-сценариев** с удерживаемыми ответами
(`artifacts/ci/test-ui.69ZY9j/`); полный UI-набор заново не запускался.
Подробности прежней матрицы —
в [плане тестирования](testing-plan.md#локальная-матрица-12112026).
Поворот проверяет реальные размеры экрана, введённый черновик и скачивание/закрытие
меню в обеих ориентациях. На iPad меню закрывается нажатием вне popover.
Для выбора документа host создаёт только синтетический `sdk-upload.txt` в Documents
и включает Files-доступ в своём Info.plist; SDK и Example эти настройки не получают.
Тест проходит системный picker, отправляет выбранные байты на loopback и проверяет
единственный POST без перезагрузки страницы. Это не проверка production-виджета.
Очистка при программном закрытии меню и загрузки
через новое окно не заявляются успешными: см. [известные ограничения](testing-plan.md#известные-ограничения-без-исправлений). Сводка и дерево `.xcresult` проходят ту же
проверку состава, что и 121 SPM-теста; пропуски и незапущенные сценарии — ошибка.
При падении сохраняются screenshot, дерево accessibility и последнее состояние.

При каждом запуске изолированный host до открытия SDK удаляет UUID-каталоги
вложений в своём tmp и очищает cookies/данные WKWebsiteDataStore. Проверки cleanup
SDK выполняются до завершения приложения, а не после этой уборки. Отдельный тест
оставляет меню с файлом открытым, сохраняет cookie/localStorage и обрывает процесс:
следующий запуск обязан удалить оставшийся каталог и не увидеть данные страницы.
Наблюдатель передаёт ошибки чтения файлов/каталогов в observationErrors; обычный
state() завершает тест ошибкой при непустом списке. Синтетическая битая ссылка
проверяет, что нечитаемое вложение не превращается в успешную проверку очистки.

Проверки сохранения страницы сравнивают её случайный pageID и число HTTP-загрузок;
основные сценарии вложений также вводят текст через XCUITest до скачивания.
Общий helper требует отсутствия файлов и каталогов. Ошибочные blob-сообщения
проверяются на настоящем экране: SDK сначала сам регистрирует readBlob при
blob-навигации, затем локальная страница отправляет неверные сообщения; ожидаются
три ошибки разбора и сохранение изменённого черновика и той же страницы.

TLS и редиректы тестируются через реальные запросы страницы до преобразования
ответа в WKDownload; destination/HTTP-статус, обрыв тела и завершение — уже через
настоящий WKDownload. Тесты не утверждают, что каждый redirect/auth callback
самого WKDownload обязательно был вызван: момент передачи зависит от WebKit.
Для незавершённой загрузки сервер отдаёт заголовки и начало большого тела,
ждёт явного разрешения теста и только затем завершает/обрывает ответ.

Основной UI runtime — iPhone 16 / iOS 18.6. Поднабор совместимости дополнительно
проверяется на iPad (A16) / iOS 18.6 и iPhone 15 / iOS 17.4; это не полный прогон
на этих устройствах. Более старые runtime, физические устройства, Firebase/APNs
и настоящий виджет остаются непроверенными. По уточнению пользователя постоянного
стенда нет, адрес из Example для тестов не используется. Декларативный закрытый Shadow
DOM по-прежнему вне поддерживаемого контракта. Сборка и зелёные тесты на iOS 18.6
не подтверждают исторически заявленную поддержку iOS 9.

## Синхронизация SDK

Источник истины — `CTChat/`. Копия — `Example/Chat/CTChat/`.

```bash
python3 scripts/sync-sdk.py --check
python3 scripts/sync-sdk.py --sync
```

`--check` ничего не меняет: сравнивает относительные пути и байты всех `.swift`,
сообщает об отсутствующих, отличающихся и лишних файлах и возвращает ненулевой
код при расхождении. В CI используется только этот режим.

`--sync` добавляет отсутствующие и обновляет отличающиеся файлы из корня.
Перед первой записью проверяет все изменяемые назначения: staged/unstaged
изменения, удаления и существующие untracked-файлы нельзя перезаписать.
Назначения с флагами Git `assume-unchanged` или `skip-worktree` также нельзя
перезаписать: команда прекращает работу до первой записи и не снимает флаги.
Если в копии есть лишние Swift-файлы, команда прекращает работу; их нужно
разобрать и удалить явно вместе со ссылками Xcode. Символические ссылки
в каталогах SDK не поддерживаются. Совпадающие файлы не переписываются.

Для новых Swift-файлов отдельно добавьте ссылки в проект Example и
Compile Sources target `Chat`: скрипт не редактирует `.pbxproj`.
Не используйте reset/checkout для обхода защиты локальных изменений.

## Диагностика и проверка ошибок

Каждая команда создаёт отдельный каталог в `artifacts/ci/` с полным
`output.log`, `.xcresult`, а для тестов — списком симуляторов, JSON-сводкой
и деревом выполненных тестов, в том числе при падении `xcodebuild`, если `.xcresult`
успел сформироваться.
Для сети добавляются `fixture.json` (UUID симулятора/runtime/порты/дата)
и `server-requests.jsonl` с синтетическими запросами, а также `fixture-errors.json`
с ошибками ожидания release (пустой список при отсутствии ошибок). Приватные ключи не попадают
в артефакты. Код ошибки `xcodebuild` сохраняется после очистки стенда.
`ARTIFACTS_DIR` позволяет выбрать другой каталог. Повторные запуски не стирают
старые результаты. DerivedData находится в `.build/ci/` и не загружается как артефакт.
Не запускайте локальные SPM build/test одновременно: они используют общий DerivedData.
`test-spm` и `test-ui` также нельзя запускать одновременно в одном worktree: оба
временно создают `Fixtures/Runtime/`; второй запуск откажется его перезаписывать.

GitHub Actions загружает диагностику через `if: always()` и хранит 14 дней,
в том числе при ошибке сборки или теста. При ошибке до создания `.xcresult`
останется текстовый лог; при принудительной остановке runner загрузка не гарантируется.
`pipefail` сохраняет ошибку команды при выводе через `tee`. Предупреждения
старого кода остаются видимыми и сами по себе не превращены в ошибки.

Для проверки инфраструктуры в отдельной временной копии репозитория:

- Изменить зеркальный Swift-файл: `--check` должен завершиться с кодом 1;
  `--sync` не должен затереть незакоммиченное изменение.
- Временно инвертировать assertion: `test-spm` должен вернуть ненулевой код,
  сохранив лог и `.xcresult` с упавшим тестом. Затем удалить временную копию.
- Проверить успешную сводку и дерево: выполнен 121 тест из манифеста,
  все прошли, пропусков нет. Удалённый, переименованный, повторный, упавший
  или пропущенный сценарий должен давать ненулевой код проверки результатов.
- В отдельной копии заменить `SecTrustSetAnchorCertificatesOnly(..., false)`
  на `true` и отключить проверку redirect-host: тесты системного доверия,
  запрета хоста и HTTP должны упасть. Убедиться, что сохранены `.xcresult`
  и журнал, а одноразовый симулятор, ключи и Runtime удалены и при отказе.

Первый реальный запуск Actions после публикации изменений необходим для проверки
закреплённого runner и скачивания артефактов. Локальные результаты подтверждают
работу скриптов только в локальном окружении.
